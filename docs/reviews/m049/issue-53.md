## 2. 전체 산출물과 우선순위

### A. 실제로 넓고 탐험할 만한 지도 (필수)

- 현재 40×25에서 **기본 목표 96×64 타일 정도**로 확대(기존 약 6배; 셀 16×16 기반). 더 큰/작은 크기가 플레이와 성능상 유리하면 근거와 비교 지표를 제시하라.
- 단순히 현재 7×6 방을 넓은 빈 들판에 드문드문 배치하지 말 것. 공통 방 슬롯을 대체해 **최소 4가지 서로 다른 공간 원형**(예: 붕괴 산업시설, 삼림/폐허 거주지, 충돌대, 폐쇄된 연구/관측 시설)을 조합. 동일 유적에도 당시 역사, 현재 damage/intact/ruined, Project·Scar·소유권에 따라 통로, 장애물, 위험, 접근 경로와 중요한 선택이 달라질 것.
- 주 경로 외에 우회로, 막힌 길, 위험 통로, 탐사 가능한 샛길, 상징적인 랜드마크가 있어야 한다. 적어도 한 의미 있는 목표에 **서로 다른 위험·자원 비용의 두 접근법**을 제공.
- 세 지역 출구를 스폰 바로 옆에 몰아 넣지 마라. 출구 찾기만 강제하는 미로도 안 된다. 탐험·보상·다음 목표가 지도 위에서 자연스럽게 보이도록 한다.
- 시작 위치/출입구, 방과 열린 지형, 대각선 코너 이동, 위험 셀, 도달성, 시야, 몬스터·오브젝트 겹침, 강제 softlock이 없어야 한다. 가변 시설 수와 다양한 Seed에서도 안정적으로 배치.
- 1개 넓은 맵만 데모로 만드는 대신 **기존 v6의 실제 Manifest에 연결된 3개 locality**를 모두 구현하고, 지역 이동·재방문 상태를 유지한다.

### B. 실제 게임에 쓰는 픽셀아트 (필수)

- **16×16 픽셀아트, nearest-neighbor, 선명한 제한 팔레트**를 기준으로 완전한 지면/벽/길/실내/폐허/물·위험/시설/문/환경 오브젝트/아이템/플레이어/적 스프라이트를 렌더에 적용한다. 개발자 문자/단색 원 플레이그라운드가 최종 결과로 남아서는 안 된다.
- 기존 EverRogue CC0를 적극 활용하되 필요한 테마별 원본 그래픽·변형 타일·환경 디테일을 **코드 기반 생성 스크립트(예: Godot Image/Python Pillow의 오프라인 빌드 도구)**로 실제 PNG atlas/이미지 파일로 출력할 수 있다. 런타임 외부 이미지 API 의존 금지. 원본/변형 픽셀의 원칙·팔레트·타일 인덱스/출처를 문서화한다. 불확실한 외부 라이선스 에셋 도입 금지. 이미지가 제대로 생성되지 않았으면 코드상 '완료'라고 하지 말고 수정.
- 단순 랜덤 색점이 아니라 형태가 읽히는 타일(땅·풀·나무·바위·건물·잔해·도구·위험·플레이어·적)을 생성하고, 테마/반복 패턴/경계 타일·오토타일과 오브젝트 시각 계층(z-index), 가림·대비·플레이어 실루엣을 고려하라.
- **실제 Godot GUI GPU 캡처**를 최소 3개의 서로 다른 역사/지도 Seed와 3가지 화면 크기(800×600, 1152×648, 1920×1080)로 남겨서 육안으로 검토하고, 필요하면 두 차례 이상 수정한다. 스크린샷을 코드의 의미와 일치시켜라.
- 96×64 확대 후 전체 맵이 화면에 작게 눌리지 않도록 **플레이어 중심 카메라(상하좌우), 맵 경계 처리, 최소한의 줌/개요 지도(확대·축소)**를 제공. 타일 크기를 희생해 전체를 한 화면에 넣는 것은 불가. 현재 한국어 안내·행동 피드백, Character Overview, 기록, F3 진단을 잃지 말고 화면을 정리하라.

### C. 다양한 절차적 오브젝트·의미 있는 상호작용 (필수)

- **기본 목표 12종 이상 오브젝트 archetype**을 구축하되 장식/장애물/자원/시설/기록/위험/랜드마크 등 역할을 구분. 장식만 12개 늘려 조건을 충족시키지 말 것. 숲·돌무더기·수레/상자·폐기 장치·시설 단말·잔해·문/펜스·컨테이너·표지·작업대·캠프·안전한 쉼터 등은 예시이며 역사/환경에 맞게 설계.
- 장식으로 배치되는 물체와 실제 상호작용 가능한 물체는 물리·충돌·시각 피드백을 일치시켜라. 오브젝트 ID/상태/소유권/실제 물량을 안정적으로 보존하고 Seed 재생성에도 결정적일 것.
- 회수→절도→자재 배상만 반복하지 않게 최소한 **합법적 자원 경로 1개**(주인 없는 환경 채집·공공 잔해·의뢰/거래 중 구현 가능한 선택)와 **비전투 목표 2개**(기록으로 안전 경로 발견·환경 안정화·고장 시설 우회/정비 등)를 실제 행동과 보상으로 연결한다.
- 새 환경 채집 자원은 **역사적 Manfest의 고유한 relic, stock/actually_present를 임의로 만들어내지 않는 별도 현재 환경 자원 계약**을 갖추어야 한다. 새로운 역사나 인간 집단·고대 기술의 기능을 발명하지 말 것.
- '세 지역을 방문했다' 대신 **실제 탐험 진행 지표**(중요 지역 발견, 공간 커버리지, 위험/목표 해결, 보상·활용, 여러 경로)와 게임 안에서 다음 목적을 알려줄 최소한의 자연스러운 UI를 추가.

### D. 기존 데이터베이스 몬스터를 실제 스폰/전투에 통합 (필수)

- 모든 적의 원본은 `CombatContentCatalog.all_hostiles()` / `CombatContentCatalog.actor(id)`, `content/catalog.tres`이다. `docs/datasets/monsters.json`만 파싱해 런타임에 별도 숫자를 넣지 말 것.
- 등록된 기존 프로토타입 예: `rat`, `feral_dog`, `wolf`, `boar`, `giant_beetle`, `cave_lizard`, `giant_spider`, `giant_crab`, `feral_ape`, `raider`, `armored_raider`. 다만 실제 `all_hostiles` 집합 및 AI/몸 템플릿을 조회해 출현 가능성을 결정하라. 적의 origin이나 인공생성 이유를 근거 없이 추가하지 말라.
- **최소 5종 이상의 서로 다른 적 유형을 테스트 Seed 전체에 걸쳐** 스폰 가능한 데이터 기반 출현 테이블을 구현. 지형/위험/현재 시설 상태·생태적 맥락에 따른 후보 가중치, 안전한 플레이어 스폰, 인접도·충돌·통로 차단·군집 규모 제한을 고려. 한 지역에 모든 적을 한꺼번에 몰지 말 것.
- 기존 공격/신체/방어/AI/시간 스케줄러 재사용; 신규 전투 계산기/AI 복제 금지. `WorldActorState.restore()`가 현재 `human`/ `rat`만 복원하고 `HistoryRuntimeState.decode()`가 rat-only 스폰을 검증하므로 **여러 기존 Actor 프로토타입으로 save/load/지역 동결·복원이 가능한 타입 안전한 확장**이 반드시 필요. 정체성이 불명확한 인구를 무조건 '적대 약탈자'로 바꾸지 말라.
- Threat Rating은 아직 검증되지 않은 null이므로 **임의 TR을 채우거나 스케일링을 도입하지 말 것**. 초기 위험은 안전지대·텔레그래프·우회 선택과 실측 전투/생존 데이터로 제한. 1:1 강제 죽음이나 무리 스폰 금지.

### E. 기존 계약·현지화·저장 (필수)

- 게임 시작 후 행동·현재 지형/오브젝트 변경·소유권·희귀 물품 단일 소유·재방문·NPC 죽음/부상·RNG·장비/효과/대기시간을 보존할 것.
- 새 맵/스폰/상태가 기존 저장 포맷과 충돌하면 **Realization/Save version을 명시적으로 올리고 안전한 마이그레이션 또는 명확한 비호환 안내**. 저장 불가하거나 무결성 오류를 무시한 로드는 금지. 기존 save 파일을 실험적으로 덮어쓰지 않도록 새 슬롯/경로 사용.
- UI 텍스트는 한국어를 기본으로 PO/GameText 구조에 추가하고 원문 영어 fallback/플레이어 문구·안내를 검증한다. 새 `LocalizationManager` 중복 도입 금지.
- 역사 생성 내용 자체를 바꾸지 않았다면 Phase A/B 및 Manifest canonical hash를 유지하라. 필요할 때만 오브젝트 실현 계층의 버전을 변경.
- 디자인은 world-first: 역사 읽기는 선택이고, 장비·탐색·회피·전투·자재·환경 사용이 플레이 동기를 만든다.

## 3. 실제 완성 판정 (모두 결과를 남길 것)

1. **플레이 시작**: Godot debug 플레이 씬(F6 또는 별도 명확한 opt-in 씬)을 사람이 열어서 바로 WASD/방향키로 플레이 가능. 96×64 수준 큰 맵에서 화면 카메라·줌·UI·스프라이트 정상. 적·장비·환경 객체가 문자 대신 픽셀아트로 구별됨.
2. **Seed 다양성**: 최소 100개 Seed × 3 지역에서 유효 스폰·실제 몬스터 후보/오브젝트 수·도달성·출구·no-softlock·결정성 검사. 가능하면 기존 500 worlds/1,500 zones도 성능 검증. Map의 크기가 증가했다는 이유로 테스트 기준을 완화하지 말 것.
3. **두 가지 전략**: 같은 Seed에서 회수 중심과 위험 회피/합법적 회수 중심 자동 플레이 모두 의미 있는 목표를 수행하도록 테스트. 진짜 행동으로 위험·전투·정보·보상이 달라져야 함. 출구 2번 이용해 3지역 달성하는 착시를 '성공'으로 계산하지 말 것.
4. **실제 적 다양성**: 최소 5종 이상의 기존 몬스터가 seed corpus에서 실제 생산 규칙으로 출현, 적 타입별 AI·공격·행동 시간·피해·사망·재방문·저장 복원 검증. 기존 전투 데이터가 그대로 쓰이는지 비교.
5. **Save/Load**: 실제 맵과 객체 영속 상태를 여러 지역 오가며 저장·복원, 구버전 저장/손상 저장 처리, 새 객체·다중 Actor 검증. 이전 Phase C 테스트와 기존 43-test gate를 함부로 삭제하지 말 것.
6. **시각적 품질**: 최소 3 Seed × 3 viewport의 실제 스크린샷, 16×16 sprite sheet/타일 검수, 시각적 결함/개선 로그. 한 번만 렌더링하고 '미학적 완성' 선언 금지.
7. **플레이 재미 검증**: 20~30분 자유 탐험의 **사람 검수는 미실시라고 명시**, 자동 행동 로그로는 목표 다양성과 위험·보상·이동 부담까지만 객관적으로 평가.
8. **수치/문서**: 지역 크기·스폰·평균 플레이 행동·보상·적 다양성·성능(mean/p95)·Seed별 문제·과거와 달라진 점을 정량 비교, `docs/ROADMAP.md`, `docs/MILESTONES.md`, `docs/milestones/M049_...`, 관련 `docs/wiki`·`docs/specs`, `THIRD_PARTY.md` 필요시 갱신.
9. **최종 인계**: 브랜치, commit SHA, 변경 파일, 출처/라이선스, Godot 실행 방법, 출력 스크린샷 경로, 통과/실패 지표, 남은 문제, main 미병합 여부를 명확히 보고.

## 4. 구현 중 우선순위와 범위 관리

작업을 **하나의 end-to-end 완료 가능한 수직 단면**으로 유지한다. A 지도→B 아트와 화면→C 오브젝트→D 적→E 테스트 순으로 검증 가능하게 나누되, 어느 한 단계가 끝났다는 이유로 메인 요구사항을 생략하지 말라. 어려운 부분은 '구현 안 됨'을 보고하고 허위 성공 처리 금지.

**반드시 구현:** 넓고 비반복적인 이동 가능한 지도, 실제 픽셀아트 렌더, 의미 있는 절차 오브젝트, Catalog 기반 다종 적, 실제 행동/영속성, 자동 검증+GPU 캡처.
**의도적으로 제외:** 전체 행성 500개 세계 실시간 시뮬레이션, 새 전투 시스템, 메인 퀘스트 장편, 복잡한 경제·외교, 미지 고대 기계 완전 작동, 모든 종족·문화 해석, 임의 레벨 오토스케일링.

최종적 질문은 **'코드가 얼마나 많이 생성됐는가'가 아니라 '다른 역사와 지역이 실제로 다른 탐험을 가능하게 하는가, 20~30분 더 돌아다니고 싶은가'**이다.
