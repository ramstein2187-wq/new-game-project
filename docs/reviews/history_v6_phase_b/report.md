# M047 History v6 Phase B — 통합 검토

기준: M045 `c0f1f920904342db37e29b585b697b6df560e6cc`에서 만든
`codex/history-generator-v6-phase-b`, Godot 4.7.2, 콘텐츠 `phase_b_1`.
이번 M047은 기존 M046 비용 질의 최적화와 별개인 작업이다. 기본 생성기는
여전히 v5이며 main 병합과 실제 플레이 시스템 연결은 수행하지 않았다.

## 구현과 판정

다섯 코어 개념과 동일한 생성 루프·선택기·원자적 리듀서·JSON 로그를 유지했다.
별도 문명사·Project·Scar 생성기를 만들지 않았다. 추가한 것은 타입이 정해진
상태, 명시적 연산, 여섯 상황 규칙, 작은 authored Project 정의와 출력 소비자다.
인구 출처, 지리, 실제 시설·자산·관리권·위험이 이후 후보와 결과를 바꾼다.

현재 출력은 앞으로 월드 생성기가 소비할 수 있는 계약이다. 지도·아이템·Actor
행동·UI·퀘스트나 실제 플레이 재미가 구현/검증됐다는 뜻은 아니다.

설계와 재현 명령의 권위 있는 문서는
[v6 계약](../../specs/history_generator_v6.md#phase-b-dynamic-civilization-explicit-opt-in),
작업 재개 기록은 [마일스톤](../../milestones/M047_history_v6_phase_b.md)이다.

## 정성 검토: 고정한 무작위 20개 세계

Seed를 비결정적인 검토 RNG로 한 번 추출하고 [목록](sample_seeds.json)에 저장했다.
결함 수정 이후에도 같은 Seed를 재생성했다. 좋은 세계만 골라 교체하거나
특정 Seed의 결과를 직접 수정하지 않았다. 아래는 AI의 실제 사건/상태 읽기
검토이며, 인간의 최종 세계관 승인이나 플레이 테스트 점수가 아니다.

모든 링크는 초기 인구·시설, 전체 시간순 사건, Project/Scar, 정치 계보,
현재 시설·자산·지리·손실과 물건의 존재 여부를 포함하는 읽기용 출력이다.
전체 기계 판독 역사와 Manifest JSON은 같은 작업트리에 보존하고 Git에서는
제외했다. 고정 Seed로 재현할 수 있고 독립 소비자용 한 Manifest는 fixture로
커밋한다. 사건이 없는 사업 종류나 Scar는 억지로 추가하지 않았다.

## 아키텍처 비교와 확장 비용

| 비교 | v5 | v6 Phase A | v6 Phase B |
| --- | --- | --- | --- |
| 흐름 | v5 planner가 v4 planner를 상속하고 scaffold/topology/episode/Project/Scar/관측/호환/투영/Claim/고고학 순서를 조정 | 현재 상태→후보→선택→효과→리듀서→로그 | 같은 루프에 시계 조건·문명 상태·여섯 상황 규칙 추가 |

| 코드 비용 | v5 접두어 7파일/602행이지만 v4 planner 338행, generator 378행, topology 304행, projector 170행, compatibility 139행 등 상속·공유 의존이 있음 | 14 GDScript/824행 | 26 GDScript/2,117행, Manifest 검증/상태 복사/연산 검증 포함 |

**v6가 전체적으로 v5보다 작거나 무조건 더 단순하다고 판정하지 않는다.**
v6의 상태 쓰기와 시간 진행 경로는 하나여서 추적하기 쉽고, v5의 상속된
planner/scaffold/topology를 따라가거나 결과에 맞춰 앞 단계 사슬을 조립하지
않는다. 반면 타입·복사·불변조건·재생·Manifest의 비용은 실제로 늘었다.
파일 수나 코드 행 수만으로 동등 기능의 우월성을 증명할 수 없고, v5에는
Phase B가 아직 제공하지 않는 authored breadth와 소비자 계약이 있다.

같은 기능/자원을 사용하는 새 소재는 definition과 후보 조합으로 확장할 수
있다. 새로운 물리 결과라면 닫힌 Effect/Reducer, 상태·복사·불변조건·JSON·
테스트·Manifest를 함께 변경해야 한다. 새 Project 하나당 거대한 새 생성기를
추가할 필요는 없지만, 무조건 데이터 한 줄로 확장된다는 주장도 하지 않는다.

## 최종 질문에 대한 답

1. 작은 코어 유지: 다섯 개념과 단일 루프 유지. 상태/검증은 크게 늘었으므로
   아직 작은 프로토타입이며 기능 비용 감시가 필요하다.
2. 별도 거대 Project/Scar 생성기: 없음. 상태 레코드·공통 규칙·리듀서 연산이다.
3. 고정 시나리오 없는 차이: 고정 최종 세력 수/사업 목록/강제 단계 사슬 없음.
   구조·현재 시설·사업 결과의 서로 다른 분포를 실제 생성에서 확인했다.
4. 후속 가능성 변화: 소유/거주/자원/위험/통로/장비 상실이 시작·인계·복구·시도
   후보를 바꾸며, 명시적 선행 근거와 JSON 재생으로 검증한다.
5. 상황적 필요: 안전/수용 압박·피난처·실제 자산·유지 필요가 후보와 가중치에
   영향을 준다. 완전한 정치 AI나 미래 사업 계획은 아니다.
6. 복구/재사용: 유한 잔존물 회수·지역 자재 수급·구조 복구·공동 유지·피난처

### 장기 실험의 해석

최초 진단에서는 17/100이 전 시설 폐허였고 100개 모두 자원/조건 고갈로
멈췄다([보존 진단](diagnostic_before_recovery.json)). 입구와 실제 인구 배치를
보완하고, 해당 지역의 피난처 필요, 한정된 자재 수급, 실제 생존 자산,
물리/기능 접근, 보관권을 수정했다. 최종에는 100개 모두 horizon까지 종료했고
전 시설 폐허 상태는 4/100으로 줄었다. 결과를 수선하거나 padding하지 않았다.

하지만 장기 안정성을 완전히 해결하지는 않았다. 시설 손상/수급/복구가
반복되고, 일부 지역 통합과 이동 왕복도 남는다. 왕복 후보는 그때의 실제
안전/수용 조건을 개선해야 하지만, 조건 있는 반복 자체를 삭제하지 않았다.
4개 폐허 세계도 후속 복구가 가능한 순간 상태인지와 실제 플레이 경험은
추가 검토가 필요하다. 인구 보존 검사는 닫힌 출처 집단 모델의 불변조건이며
6,000년 인구 예측·개별 인간 수명 검증이 아니다.
