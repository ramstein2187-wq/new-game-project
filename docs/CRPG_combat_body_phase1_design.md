# 전투·신체 시스템 설계 및 1차 구현 명세

> 상태: M017 기능 브랜치 구현 및 자동 검증 완료 / 수동 플레이·main 통합 대기. 작성·갱신일: 2026-09-21. 프로젝트: Godot 싱글 개발 CRPG.
> 적용 대상: 현재 플레이어 vs 쥐 테스트 환경. 이 문서의 수치와 이름은 **실험용 기본값**이며 밸런스 확정이 아니다.
> Codex는 실제 코드·AGENTS.md·마일스톤/decision/follow-up 문서를 먼저 확인하고 충돌이 있으면 기존 규칙을 존중하며 변경사항을 명시할 것.

실제 구현·검증·수동 플레이 절차는 [M017](milestones/M017_combat_body_phase1.md), 지속할 판단은 [전투·신체 decision](decisions/combat_body_phase1.md)을 참조한다. 아래 원칙은 유지하며, 모호했던 동작과 임시 수치는 다음과 같이 구체화했다.

### M017 구현에서 확정한 실험 규칙

- 기존 HP 5/3·피해 1에서는 아래 건전성 수치로 기능 변화를 보기 어려워 **HP 50/30·기본 피해 5**로 변경. 부위 건전성·가중치는 아래 표 유지, 몸통 A=100·공격 P=20, 부분 피해는 3. 양쪽 공격은 임시 Sharp. 쥐 공포는 잃은 HP 비율 ×120으로 정규화하여 기존 성향·후퇴 기준을 보존한다.
- 기존 능력치/DV 규칙이 없어서 인간 STR·쥐 DEX, DV=10+DEX 보정 채택. 손상된 공격 부위는 상황 보정 -2; 기본 능력치는 변경하지 않는다.
- 공격 기능 부위를 생성 시 연결한다. 현재 인간형의 오른팔이며 종족/부위 ID 분기로 판정하지 않는다. 반대팔 자동 전환은 제외.
- 보행 기능 기여는 정상 1·손상 0.5·상실 0의 평균, 실제 비용은 `ceil(기존 비용 / 기여도)`. 인간 다리 1개 손상 시 1334, 쥐 다리 1개 손상 시 858. 모든 보행 기능 상실 시 이동 불가.
- 머리/몸통 건전성 0은 해당 부위 및 연결된 자식의 기능을 막는다. **전체 HP 0만 기존 사망 경로를 실행**한다. 머리 0의 살아 있는 쥐는 물기 불가. 파괴된 부위는 여전히 피격 대상이며 절단으로 처리하지 않는다.
- 빗나감·완전 방어는 정상 공격 시간(1250/1000) 소비. 기능 부족/거리 등 유효하지 않은 행동은 기존 규칙대로 시간·난수·로그 소비 없이 거절. AI는 기존 후보 유효성 필터와 대기로 정지를 방지한다.
- 전투 시드 기본 17017, 개체 상태와 함께 전체 reset 시 재설정. 맵 생성 시드와 독립적이며 능력치 초기화 버튼은 HP/부상/시간/전투 난수를 바꾸지 않는다. 생성 맵의 R은 새 게임을 만들고 패널 연결도 갱신한다.
- 15개 자동 테스트와 실제 피격 통합 검증 통과. 500시드 인접 전투 표본에서 쥐 다리 손상 443, 물기 저하 247, 플레이어 팔 손상 32; 496회는 후퇴로 거리 벌어짐. 팔 기능 상실은 통제된 실제 피격 테스트에서 검증했고 자연 교전 표본에서는 0회여서 빈도 조정은 follow-up이다. 수동 플레이는 미수행이며 **1차 전체 완료로 간주하지 않는다**.

## 1. 설계 목적과 불변 원칙

- 기본 명중 및 향후 비전투 판정: **D20 + 관련 능력치 보정 + 숙련/상황 보정**.
- 명중 → 피격 부위 → 한 겹 방어구 → 피해 → 부위별 부상 → 신체 기능 변화 → 행동 가능 여부/비용 갱신을 구분한다.
- **신체의 형태·상태가 실제로 가능한 행동과 전투 전략을 바꿔야 한다.** 단순 능력치 페널티만으로 끝내지 않는다.
- Qud에서 참고할 점은 **변할 수 있는 신체 구조**, RimWorld에서 참고할 점은 **부위별 기능 저하와 유효 방어력 판정**이다. 해당 게임의 전체 규칙을 복제하지 않는다.
- 기존 턴·시간(M011 계열), 공통 Action, 플레이어 조작, 쥐 AI(접근·공격·후퇴 등), 로그, 체력·사망 경로를 우선 보존한다.
- 플레이어와 쥐는 **동일한 공통 데이터/판정 시스템**을 사용하되 종족·신체 크기·부위 구성·공격 방식은 다르게 설정한다.
- 향후 팔 추가, 절단, 촉수, 의체, 다중 무기, 다른 생물의 신체 템플릿으로 확장할 수 있게 하되 **이번에는 구현하지 않는다**.
- 템플릿 정의와 개체별 상태를 분리하고, 판정 확률 계산은 실제 전투 난수 상태를 소비하지 않는다.

## 2. 범위와 단계

**1차 필수:** 기본 6능력치 및 실험용 분배 UI, D20 공통 판정과 실제 공격 연결, 인간형/4족보행형 템플릿 및 개체별 부위 건전성, 명중 부위 선택, 몸통 보호구 한 겹, 유효 방어력 3결과, 부상에 따른 플레이어 공격 및 쥐 이동·물기 영향, 기존 로그·AI·시간 시스템 연동, 자동 및 수동 검증.

**1차 제외:** 정식 캐릭터 생성/성장, 신체 부위 추가·절단·재생·의체, 여러 무기/복합 행동, 손·눈·장기 별도 피격, 출혈·통증·감염·치료, 부위 지정 공격/치명타, 다층 갑옷·내구도, 새로운 종족 전체, 고급 AI 재작성, 월드 영속성의 신체 상태 연동.

작업은 작은 단위로 진행하되, **최소 1종의 부상에 의한 행동 가능 여부 변화와 1종의 이동 비용 변화는 실제로 구현**해야 한다.

## 3. 능력치 및 실험용 UI

| 능력치 | 약어 | 플레이어 초기값 | 1차 역할 예시 |
|---|---|---:|---|
| 근력 | STR | 10 | 기존 근력 기반 공격의 보정 |
| 민첩 | DEX | 10 | DV 및 관련 공격 보정 |
| 건강 | CON | 10 | 향후 생존력/신체 저항; 부위 크기와 직접 동일시하지 않음 |
| 지능 | INT | 10 | 향후 지식·제작 등 비전투 판정 |
| 지혜 | WIS | 10 | 향후 지각·생존 판정 |
| 매력 | CHA | 10 | 향후 대화·사회적 판정 |

D&D에는 기본 능력치가 **6개**다. 보정 공식 `floor((score - 10) / 2)`; 음수도 올바르게 처리한다. 쥐도 공통 능력치 데이터 구조를 사용하며 **실험 초기값은 전부 10**으로 해도 된다. 쥐의 크기·부위 건전성·공격 방식은 능력치와 별도이다. 종족별 수치 밸런싱은 후속 과제다.

개발자용 UI: 각 수치 기본 10, **분배 포인트 12**, 최소 10, 최대 16, 각 행 `- / 현재값(보정치) / +`, 남은 포인트, 능력치 초기화. 감소로 포인트를 회수하며 초기화는 **부상/현재 체력을 회복하지 않는다**. 능력치 변경은 다음 행동부터 적용하며 진행 중 판정을 소급 변경하지 않는다. UI는 기존 테스트 방의 조작·맵·로그를 가리지 않게 한다. 정식 포인트 바이 규칙을 구현하는 것은 아니다.

기본 능력치, 장비/상황 보정, 부상에 따른 행동 효율을 구분한다. 부상으로 기본 DEX를 영구 수정하지 않는다.

## 4. D20 명중 및 피격 부위

`hit = (d20 + relevant_ability_mod + proficiency_mod + situation_mod) >= target_DV`

- 기존 공격에 정의된 관련 능력치가 있으면 그 규칙을 존중한다. 없을 경우 인간 기본 근접 공격은 STR, 쥐의 물기는 DEX를 실험용으로 사용한다. 숙련/상황 보정 기본값 0.
- DV가 미정이면 `10 + DEX_mod`를 임시 사용한다. 기존 DV 규칙이 있으면 우선 확인한다.
- 자연 1/20 자동 실패·자동 성공·치명타는 기존 규칙이 없으면 이번에 도입하지 않는다.
- 명중 실패 시 부위/방어구/피해 판정을 호출하지 않는다. 공통 D20 함수는 향후 비전투에도 재사용 가능하게 한다.
- **명중 후 별도 난수**로 유효한 신체 부위 중 하나를 가중 추첨한다. 이번에는 부위 지정 공격이 없다.

| 부위 | 인간 피격 가중치 | 쥐 피격 가중치 |
|---|---:|---:|
| 머리 | 15 | 15 |
| 몸통 | 45 | 45 |
| 왼팔/왼앞다리 | 10 | 10 |
| 오른팔/오른앞다리 | 10 | 10 |
| 왼다리/왼뒷다리 | 10 | 10 |
| 오른다리/오른뒷다리 | 10 | 10 |
| 꼬리 | 해당 없음 | 0 (부위 존재, 피격 제외) |

가중치 합은 피격 가능한 부위 기준으로 정규화한다. 0인 부위와 없는/제거된 부위는 추첨에서 제외하고, 후보가 없을 때는 안전하게 실패 처리한다. 향후 자세·크기·엄폐 보정은 별도 확장한다.

## 5. 종족·템플릿·개체 신체 구조

**Species → Body Template → (향후 Body Modifiers) → Body Instance → Capabilities → Available Actions**.

- Species: 인간, 쥐처럼 기본 템플릿, 신체 크기, 초기 특성·공격을 결정.
- Body Template: 생성 시 기본 부위와 연결, 크기/내구도 기준, 피격 가중치, 기능을 정의.
- Body Instance: 각 개체만의 부위별 현재 건전성·부상·기능·장비. 공유 Resource를 변경해 모든 쥐가 동시에 부상당하지 않도록 한다.
- Capabilities: 현재 실제 신체·장비·부상에서 도출한 `weapon_manipulation`, `bite`, `locomotion` 등. 코드에 특정 종족이나 `right_arm`이 반드시 필요하다고 하드코딩하지 않는다.

**이번의 실제 템플릿:**

| 인간형 | 4족보행형(쥐) |
|---|---|
| 몸통·머리·왼팔·오른팔·왼다리·오른다리 | 몸통·머리·왼앞다리·오른앞다리·왼뒷다리·오른뒷다리·꼬리 |
| 팔: 무기 조작 / 다리: 보행 | 머리: 물기 / 네 다리: 보행 / 꼬리: 이번엔 데이터만 |

각 부위에 개체 내 **안정적인 고유 ID**, 유형·이름·부모 부위·최대/현재 건전성·기능·가중치·보호 범위를 둘 수 있게 설계한다. 동일한 유형의 팔을 향후 여러 개 추가할 수 있어야 한다. 연결된 부모가 기능 상실하면 자식 기능에도 영향이 있을 수 있지만 부모의 가벼운 상처가 자식 부위를 자동 파괴하지 않는다.

향후 분류는 인간형·인간형 변형·4족보행형·4족보행형 변형·기타 비인간형. **변형형을 별도의 고정 종족/코드 유형으로 강제하지 말고 기본 템플릿의 개체별 변경으로 표현한다.** 거미·뱀·슬라임 같은 기타 비인간형은 필요할 때 별도 템플릿을 만든다.

## 6. 한 겹 방어구와 유효 방어력

이 문서는 **RimWorld의 유효 방어력 아이디어를 차용한 자체 실험 규칙**이다. 명중 여부는 D20으로, 방어 결과는 **별도 난수 판정**으로 결정한다.

`E = clamp(A - P, 0, 200)`

- `A`: 해당 **피격 부위에 적용되는** 방어력(%); `P`: 공격 관통력(%p); `E`: 유효 방어력(%).
- `p(full_block) = min(E/2, 100)`
- `p(partial_block) = min(E/2, 100 - p(full_block))`
- `p(bypass) = 100 - p(full_block) - p(partial_block)`

| E | 완전 방어 | 부분 방어 | 방어 실패 |
|---:|---:|---:|---:|
| 0 | 0% | 0% | 100% |
| 80 | 40% | 40% | 20% |
| 100 | 50% | 50% | 0% |
| 150 | 75% | 25% | 0% |
| 200 | 100% | 0% | 0% |

완전 방어: 신체 피해 0. 부분 방어: 기본 피해 50% (정수 피해에서는 **양수라면 올림**을 우선 실험) 및 Sharp → Blunt 전환. 방어 실패: 기본 피해 100%. 무기·기존 피해량 계산 로직은 최대한 재사용한다. 최소 Sharp/Blunt 구분을 제공하고 추후 피해 유형 확장 가능하게 한다.

**이번에는 몸통만 보호한다.** 플레이어 몸통에 가상의 실험용 갑옷 1개, 쥐 몸통에 가상의 실험용 보호구 1개. 머리·사지는 무장갑. 임시값 `A=100`, `P=20`을 실험할 수 있으나 기존 피해량을 확인하여 조정한다. 방어구가 없으면 **방어 추첨 없이** 피해가 통과한다. 한 번의 피격에 적용되는 방어구 층은 최대 하나; 인벤토리·장비 장착 UI·내구도는 이번에 만들지 않는다.

부분 방어의 둔격 전환은 전달 피해의 유형이며, 출혈/골절 등 상세 부상 생성은 1차 범위 밖이다. 1회의 방어 판정과 확률 계산을 별도 테스트한다.

## 7. 피해·신체 부상·전체 HP

**부위별 건전성(Part Integrity)**과 기존 캐릭터의 **전체 HP**를 구분한다. 하나의 공격에서 실제 전달 피해가 예컨대 5면 해당 부위 건전성 5 감소 + 전체 HP에 5가 **한 번** 반영된다. 이후 부위 피해 합계를 다시 전체 HP에서 차감하지 않는다. 기존 체력·사망 처리를 중복 구현하지 않는다.

임시 최대 건전성:

| 부위 | 인간 | 쥐 |
|---|---:|---:|
| 머리 | 20 | 8 |
| 몸통 | 40 | 16 |
| 팔/앞다리 각각 | 20 | 6 |
| 다리/뒷다리 각각 | 25 | 8 |
| 꼬리 | 없음 | 4 |

부위 상태: 정상 `>50%`, 손상 `>0%~50%`, 기능 상실 `0%`. 상태 임계값은 테스트용이며 최대 건전성 비율로 계산한다. 손상은 **관련 기능의 행동 효율 저하**, 기능 상실은 **해당 기능을 필요로 하는 행동 불가**. 기능 상실은 절단·부위 제거가 아니다.

기존 HP=0 및 사망/전투 불능 경로가 우선한다. 중요 부위(머리·몸통) 건전성 0의 결과는 **기존 사망 처리와 중복되지 않는 한 가지 명시적 규칙**으로 정한다. 단, 머리의 중간 손상에서 물기 명중 저하를 실험할 수 있어야 한다. 사지 기능 상실만으로 즉시 사망시키지는 않는다. 부위별 건전성·부상·치료·신체 변형을 서로 혼동하지 않는다.

## 8. 행동과 AI 연결: 핵심 성공 조건

- 인간의 기존 무기 공격은 조작 기능이 필요한 부위를 참조한다. 그 부위 손상 시 실제 명중/효율 저하, 기능 상실 시 관련 공격 불가. 반대팔 사용 기능이 기존에 없다면 이번에 전체 장비 교체 시스템을 새로 만들 필요는 없다.
- 쥐의 물기는 머리의 `bite` 기능을 참조한다. 앞다리가 손상되어도 물기는 정상 사용 가능; 머리가 손상되면 물기 효율이 떨어지고 기능 상실 시 사용할 수 없다.
- 인간 다리 2개와 쥐 다리 4개는 별도의 **보행 기능 기여**를 계산한다. 다리 손상 시 이동 **실제 시간 비용** 증가, 쥐의 기존 접근·후퇴에도 동일한 비용 적용. 4족 생물의 다리 하나 부상과 인간 다리 하나 부상이 무조건 같은 효과일 필요는 없다.
- 기존 Action의 실행 시점·시간 소비·동시 시점 규칙을 유지. 빗나감/완전 방어/행동 불능의 시간 소비는 기존 규칙을 확인해 명시한다. 중복 공격이나 시간 이중 차감 방지.
- 쥐가 불가능한 물기/이동을 무한 선택해 턴이 정지되지 않도록 대체 행동 또는 명시적 실패 처리를 제공한다. 고급 부상 전술 AI 재설계는 1차 범위 밖.
- 일반 전투 로그는 실제 발생한 사건만 요약하고 개발자 상세 로그에는 D20, 보정·DV, 피격 부위, E, 방어 결과, 전달 피해 및 부위 변화 등을 기록. **실제로 계산하지 않은 AI의 의도를 지어내지 않는다.**

## 9. 난수·밸런스·테스트 기준

- 난수 시드와 행동 순서를 고정한 재현성 테스트를 제공. 전투 난수와 절차적 월드 생성 난수를 불필요하게 공유하지 않는다.
- 수학적 확률 함수는 **결정적 단위 테스트**로 검증하고, 무작위 분포 실험은 보조 테스트로 사용한다.
- 초기 피격/방어구/부위 건전성 수치는 **설계 검증값**이다. 실제 HP·피해 스케일을 확인한 후 테스트 가능한 값으로 조정하되 문서에 변경을 기록한다.

필수 검증 시나리오:

1. 플레이어 여섯 능력치 기본 10, 12포인트 UI에서 분배·회수·상한·초기화가 동작하고 변경값이 다음 행동에 반영된다. 초기화해도 부상은 유지된다.
2. D20 비교 경계값(합계=DV)을 포함한 명중/빗나감, 공격자별 능력치 보정, 전투 판정과 비전투용 공통 함수의 분리가 맞다.
3. 피격 가중치와 선택 가능한 부위만 추첨하는 규칙, 방어구가 몸통에서만 작동하는 규칙이 맞다.
4. E=0/80/100/150/200의 방어 확률이 표와 일치하고 완전/부분/실패 피해 및 Sharp→Blunt가 맞다.
5. 개체 두 마리가 같은 템플릿을 쓰더라도 한 마리의 부상이 다른 마리에게 전파되지 않는다.
6. 오른팔 부상 → 해당 팔 사용 공격 변화, 쥐 앞다리 부상 → 이동 비용 증가 및 물기 유지, 쥐 머리 손상 → 물기 효율 감소/상실이 실제 동작한다.
7. 전체 HP의 중복 차감과 사망 중복 처리, 공격·시간 비용 중복이 없다.
8. 기존 쥐 접근·공격·후퇴, 플레이어 조작, 로그, 턴·시간, 게임 실행의 회귀 테스트를 통과한다.
9. 동일 초기 상태/시드/행동 순서에서 동일한 전투 결과를 재현한다.
10. 실제 Godot 수동 플레이가 불가한 실행 환경이라면 자동 테스트 결과와 **미수행 수동 테스트**를 구별하고 구체적 실행 방법을 제공한다.
